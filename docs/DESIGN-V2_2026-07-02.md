# AI Mirror v2 — Analysis Engine, Show-Back & Delivery Design

**Date:** 2026-07-02 · **Status:** Implementation basis for v2 (this doc describes what is being built, not an aspiration)

## Why v2

v1.1's "analysis" is a single LLM call over the last 400 messages (truncated), with free-text
"evidence" the model can invent, placeholder fallbacks that look like reports, and no notion of
time. It produced the two failure modes this project exists to eliminate:

1. **Sycophancy / hallucination** — claims with no verifiable grounding, flattering by default.
2. **Pendulum overcorrection** — when challenged, terse hostile output instead of calibrated revision.

v2 makes both failure modes structural non-options: every claim must carry evidence that the
*backend verifies against the actual messages*, every claim carries calibrated confidence, and an
adversarial critic pass reviews the draft before it is stored. Tone is a contract: candid,
warm-neutral, evidence-first — enforced by the critic, not by vibes.

## The seven upgrades

### 1. Evidence-grounded claims (anti-hallucination)
Report blocks gain `structured.claims[]`: `{claim, confidence: high|med|low, evidence: [{message_id, quote}], counter_evidence}`.
After generation, the backend **verifies each quote against the referenced message row**
(normalized substring / fuzzy match). Verified quotes get `verified: true` and become clickable
links into the conversation. Unverified evidence is flagged, and claims with zero verified
evidence are demoted to `confidence: low` + marked `ungrounded`. Gauges are recomputed partly
from the verified-claim distribution — no more single-shot vibes numbers.

### 2. Adversarial critique pass (anti-sycophancy)
A second, independent LLM pass (hard tier) receives the draft blocks + a corpus sample and is
instructed to *refute*: find flattery, overreach, unsupported claims, missing counter-evidence.
Its verdicts are stored as a `critique` block on the report and applied as annotations/demotions.
The report you see has survived its own hostile review, and shows you where it was weakened.

### 3. Temporal engine — epoch tables + synthetic extrapolation
- **Deterministic epoch stats (SQL, no LLM):** per month × source — conversations, messages,
  user-message length, question ratio, activity spread. Stored in `epoch_profiles.stats`.
- **Epoch profiles (scaffold tier):** compact JSON per epoch — themes, sophistication,
  delegation-to-AI level, valence, shifts. Cached; only new/changed epochs re-profiled.
- **Trajectories (hard tier):** from the observed epoch table, synthesize per-metric series
  extrapolated 2 epochs forward — every synthetic point is explicitly `kind: "extrapolated"`
  with a confidence band and stated assumptions. Stored in `trajectories`, rendered as
  observed-vs-projected tables/sparklines. This is the "deeper abstraction" substrate: the
  synthesis prompt reasons over the tables, not raw chat soup.

### 4. Meta-analysis across mirror runs
`POST /reports/meta-analysis` compares the last N full-mirror reports: which traits are stable
(test-retest), which claims drifted, what genuinely changed vs. what the model just said
differently. Longitudinal self-knowledge instead of N disconnected snapshots.

### 5. Opportunity engine (angles a human didn't design in)
Deterministic candidates + hard-tier synthesis for **unrealized angles**: dropped threads
(conversations ending on an open user question), aptitudes demonstrated but never exploited,
cross-domain transfer (patterns mastered in domain A, absent in adjacent domain B), and
questions-never-asked. Emitted as an `unrealized_opportunities` block with evidence like
everything else.

### 6. Hierarchical corpus (map → reduce)
Per-conversation summaries (scaffold tier, cached in `conversations.summary`) + stratified
sampling across epochs replace "last 400 messages." Synthesis sees the whole history's shape,
with raw excerpts where they matter.

### 7. Honest empty states
Placeholder output is gone as a look-alike: reports carry `model_used=None` → UI renders an
explicit NOT-ANALYZED banner, never placeholder prose styled like insight.

## Fable mode (tiered models)

`chat_json(..., tier="scaffold"|"hard")`. When fable mode is on (env `FABLE_MODE=true` or
request `fable: true`):

| tier | used for | default model |
|---|---|---|
| scaffold | conversation summaries, epoch profiles, extraction | `claude-sonnet-4-6` |
| hard | report synthesis, trajectories, meta-analysis, adversarial critique | `claude-fable-5` |

Not a hard rule — routing is per-call-site and configurable (`SCAFFOLD_MODEL`, `HARD_MODEL`).
Fable mode off → everything uses `LLM_MODEL` as before.

**New provider: `claude_cli`** — shells to the local `claude -p --model … --output-format json`
binary (subscription OAuth, zero API keys on disk, local-first). This is the default dev/e2e
path on the Mac Mini. API providers (anthropic/openai/grok/ollama) unchanged; the
`xai` vs `grok` provider-name mismatch from v1.1 is fixed (both accepted).

## Remote input extraction

`POST /ingest/remote` — the system pulls conversational inputs itself instead of waiting for a
manual export upload. Connectors:

- `claude_code` — scans `~/.claude/projects/**/*.jsonl` (existing parser, incremental by mtime)
- `openclaw` — parses OpenClaw v3 session JSONL (`~/.openclaw/agents/*/sessions/*.jsonl`)
- `path` — any directory, **restricted to allow-listed roots** (`INGEST_ALLOWED_ROOTS`)

Security posture: API stays loopback-only; the connector reads only under allow-listed roots;
no directive execution from ingested content (data, never instructions). Docker users mount
sources read-only; native run (dev default) reads in place.

## Show-back / UI

Keep the HUD identity, upgrade the information density where it earns it:
- **Dashboard**: LAST MIRROR RUN panel gains a *since-last-run delta strip* (meta-analysis
  hooks), a Trajectories panel (hand-rolled SVG sparklines, observed solid / extrapolated
  dashed + band), and a "Pull from this machine" remote-ingest action.
- **ReportViewer**: claims rendered as first-class objects — confidence badge, verified-evidence
  chips linking to the real message, counter-evidence, `ungrounded` styling, critique verdict
  panel.
- **Trajectories view**: the temporal tables themselves — observed vs synthetic rows, explicitly
  labelled.

## Data model additions

- `epoch_profiles(id, epoch_start, epoch_kind, source_slug?, stats JSON, profile JSON, model_used, created_at)` — unique (epoch_start, epoch_kind, source_slug)
- `trajectories(id, report_id FK, metric, series JSON, narrative, assumptions, model_used, created_at)`
- `reports.kind` gains `meta_analysis`; `deep_dive` becomes filterable (v1.1 gap)
- `report_blocks.structured.claims[]` (schema above) — no migration needed (JSON)

## Verification bar (definition of done)

Real end-to-end on this box, no mocks: remote-extract real Claude Code sessions → epoch tables
materialized → full mirror v2 with fable mode → every displayed evidence chip resolves to a real
message row → critique block present → UI renders it. Then the repo README is rewritten to
describe the *actual system* and pushed.
